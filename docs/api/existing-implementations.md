# Existing CORE search implementations

Reviewed on **2026-11-22** for an Angular 20+ research search UI with Boolean Works search, a configurable page size, and a chart based on the whole query. The review covered CORE's service page and GitHub organization, public repositories and package registries, and public OpenAPI catalogs. Maintenance observations reflect the sources available on the review date. [Project brief](../project.md), [CORE's linked SDKs](https://core.ac.uk/services/api), [CORE GitHub organization](https://github.com/oacore)

## Specifications and client generation

- **CORE OpenAPI v3.** Provider-published JSON for v3. CORE was updating the reference in October 2025. CORE links its service terms, and a separate redistribution license for the JSON could not be checked because retrieval returned HTTP 403. Publisher code confirms Works search and query aggregation. Prefer the official spec after retrieval and review. Use the local evidence-based subset to generate the app's client in the meantime. [Official JSON](https://api.core.ac.uk/swagger/v3.json), [v3 reference](https://api.core.ac.uk/docs/v3), [documentation update](https://oacore.github.io/content/images/pdfs/core-community-newsletter-october-2025-.pdf), [CORE terms](https://core.ac.uk/terms)
- **CORE v2 Swagger in public catalogs.** The OpenAPI Catalog lists a Swagger 2.0 document for the legacy v2 service and dates its listing change to November 2025. A separate reuse license for this API document was unverified. It covers legacy article, journal, and repository operations. The v3 Works search, cursor, and aggregate contracts require v3 sources. Keep the catalog entry as historical reference. [OpenAPI Catalog v2 listing](https://openapicatalog.com/apis/core-api-v2), [Jentic v2 catalog and v3 artifact link](https://jentic.com/apis/core.ac.uk/core-ac-uk)
- **OpenAPI Generator `typescript-angular`.** Apache-2.0, stable generator with ongoing releases. The `ngVersion` option supports Angular 20. The generator can produce typed methods and models for the operations and pagination parameters in the input contract. Chart coverage checks, throttling, authentication placement, and UI state belong in the app. Reuse the generator with a pinned version. [Angular generator options](https://openapi-generator.tech/docs/generators/typescript-angular/), [license](https://github.com/OpenAPITools/openapi-generator/blob/master/LICENSE), [release history](https://github.com/OpenAPITools/openapi-generator/releases)

## Official and community clients

- **CORE `pyoacore` and `oacore4j`.** MIT. Both repositories appear in CORE's GitHub listing, and their published examples use the legacy `articles/get` interface. The Java README traces to the 2017 sprint. The Python client exposes a generated legacy API, and the Java client uses typed Retrofit calls. No supported release was found for the v3 Works search, offset or scroll, and aggregation flows. Keep both as legacy references. [Python client](https://github.com/oacore/pyoacore), [Java client](https://github.com/oacore/oacore4j), [CORE GitHub activity](https://github.com/oacore)
- **rOpenSci `rcoreoa`.** MIT, archived September 2022. The R client provides legacy search and page/size options. No v3 Works, scroll, or grouped counts support was found. Keep it as a historical analysis example. [R client and archive notice](https://github.com/ropensci-archive/rcoreoa), [search interface](https://github.com/ropensci-archive/rcoreoa/blob/master/R/core_search.R)
- **Rust `core_api_client`.** MIT. Version 1.1.0 is the most recent release surfaced in the review. The typed v3 client covers Works search, query construction, and offset/limit paging. Its documented search model has a scroll ID field, which alone does not establish that a cursor loop works. No grouped-counts method was found. Use it as a corroborating reference for offset pagination. It would require a separate Rust service to use with Angular. [Package documentation](https://docs.rs/crate/core_api_client/1.1.0), [request source](https://docs.rs/core_api_client/latest/src/core_api_client/models/api.rs.html)
- **ToolUniverse CORE integration.** Apache-2.0 and actively releasing. The Python integration sends v3 Works queries, supports limit and offset, and maps paper metadata. Its published CORE adapter focuses on search and work retrieval. No native grouped-count operation or scroll traversal surfaced in its reviewed interface. Adapt the idea of validating response shape and surfacing incomplete results. A Python agent framework would add an extra runtime to this application. [CORE adapter source](https://zitniklab.hms.harvard.edu/ToolUniverse/_modules/tooluniverse/core_tool.html), [license](https://github.com/mims-harvard/ToolUniverse/blob/main/LICENSE), [releases](https://github.com/mims-harvard/ToolUniverse/releases)
- **Pipeworx CORE Research.** MIT community MCP package. Its public repository showed recent activity, with no long-term maintenance commitment identified. It uses v3 Works keyword search with a result limit and single-work metadata. Its tool interface exposes neither offset/scroll continuation nor grouped counts. Useful for corroborating the search route and response field selection. The MCP interface adds a layer the app does not need. [Repository and tool interface](https://github.com/pipeworx-io/mcp-core-research)

## Example applications and Angular components

- **CORE Search.** MIT, active in CORE's GitHub listing in September 2026. The Next.js/React site is an official v3 integration. It combines Works search, page navigation, and a separate aggregation call with year and other facets. Its build uses CORE-specific packages and a package-read token. Adapt the pattern of making the result list and the facet request independently. Its UI stack and service configuration make it unsuitable as the Angular application base, and its facet UI provides no completeness guarantee for this project's chart. [CORE Search repository](https://github.com/oacore/search), [repository activity](https://github.com/oacore), [search and aggregation calls](https://github.com/oacore/search/blob/main/api/search.js), [facet state](https://github.com/oacore/search/blob/main/store/filters.js)
- **CORE `gpt-core`.** Apache-2.0 example repository with activity listed in August 2026. Its Python service calls v3 Works with a limit and can pass scroll cursors. It has no grouped-count operation or Angular UI. Adapt its bearer and cursor examples, and use bounded retries and normal TLS certificate verification in app code. [Repository and license](https://github.com/oacore/gpt-core), [search helper](https://github.com/oacore/gpt-core/blob/main/core.py), [repository activity](https://github.com/oacore)
- **Collaborative Science Platform practice app.** Archived November 2025. No repository license was identified. Its practice endpoint wraps a v3 Works GET and exposes a keyword and page-size input. The example fetches the first page and has no cursor or aggregate flow. Its sanitized wire observations inform the local contract. Reimplementation is more suitable than copying code from this archived project. [Repository and archive notice](https://github.com/bounswe/bounswe2023group9), [project team's integration record and sample response](https://github-wiki-see.page/m/bounswe/bounswe2023group9/wiki/Milestone-2-Report)
- **Angular Material paginator.** MIT and actively released, with an Angular 20 release. It provides page index, page size, and total length controls independently of the API. An app can translate its page events into `offset` and `limit`, and constrain navigation to the accessible window. Query parsing, cursor support, and aggregation are outside the component. Reuse it if Angular Material fits the app's design. [Paginator source](https://github.com/angular/components/blob/main/src/material/paginator/paginator.ts), [Angular 20 release](https://github.com/angular/components/releases/tag/20.0.0), [repository and license](https://github.com/angular/components)

## Reuse decision

The review found no suitable ready-made CORE v3 Angular SDK or Angular research-search application with Boolean Works search, pagination, and verified complete-query aggregation. Generate a thin client from the [local contract](core-v3.openapi.yaml), adapt the provider's separate search and aggregation requests, and implement the application-specific search state and coverage checks in Angular and its server integration. [Scope and prerequisites for the chart](core-api.md#complete-query-aggregation)
